# 界面文案规范

适用于 `src/app.js` 中的页面文本、按钮、提示条与确认框，以及领域层返回给玩家的错误信息。`rules/` 下的事件、NPC 与路线文本属于冻结规则内容，修改需要发布新的规则版本（见 `rules/ruleset_manifest.js`）。

## 原则

1. **说明功能或结果，不写修辞。** 标题用名词短语描述页面或状态，例如「本周总览」「本周已结算」，不用设问或比喻。
2. **只写玩家需要知道的规则。** 写清"会发生什么、需要什么条件"。不写系统"不会做什么"的自我说明，例如「不会因反复打开页面重抽」「筛选不会改变账务」。
3. **不暴露实现细节。** 不出现随机种子、检查点、原子提交、冻结快照、白名单、默认折叠等开发术语，也不显示英文枚举值。
4. **一句话说完。** 说明文字每处一句，最多两句；超出的放进折叠详情或确认卡。
5. **不重复同一个免责声明。** "模拟货币 / 不连接真实账号"只出现在页脚和创建页。

## 句式

| 场景 | 写法 | 示例 |
|---|---|---|
| 页面标题 | 名词短语 | 本周排期、个人账本 |
| 小标题（eyebrow） | 中文，用「·」分隔 | 第 3 周 · 14 个时间格 |
| 按钮 | 动词开头，必要时带「→」 | 推进本周 →、提交申请 |
| 成功提示 | 结果陈述，句号结尾 | 存档已导入。 |
| 失败提示 | 原因 + 存档状态 + 下一步 | 提交失败，存档未改变，可以重试。 |
| 确认框 | 「确认 + 动作？」+ 一句关键后果 | 确认撤回申请？申请记录将保留。 |
| 空状态 | 「尚无…」+ 何时出现 | 尚无已结算周报 / 完成第一周结算后显示。 |

## 术语表

| 统一用 | 不再使用 |
|---|---|
| 存档 | 运行档、正式存档（与备份区分时可用「主存档」） |
| 推进本周（操作）、周结算（过程） | 周推进、执行本周 |
| 时间格；计数工作时用「工作格」 | 格位、slot |
| 默认选项 | 安全默认 |
| 平台分成后收入 | 平台后收入、平台后口径 |
| 主播应得 | 主播归属（「SC归属收益」为规格指定名称，保留） |
| 待交付商单 | 已签交付 |
| 模型估计值 | 聚合模型估计 |
| 规则版本 | 规则快照、冻结模式 |
| 结束生涯 | 收束 |

## 规格强制保留

以下写法由 `game_development_spec.md` 规定，改写时不得删除：

- 独立观众、近 28 日活跃等模型值必须标注「估计」或「约」（§9）。
- 会员与观众预算周期称「消费周期」（§0）。
- 税费简化时标注「简化税费」（§11）。
- 教程奖励标注「教程效果」（§18）。
- 企业合同数值标注为设计参数，不代表真实企业（§26）。
- SC 总额标题写完整，不得让玩家误认为是到手收入（§11）。
- 空状态：未开通显示「未开通」，无直播时同接显示「—」（§19.3）。
- 重大操作确认卡包含：当前方案、费用、失去的权限、保留的资产、未解决事项（§19.4）。
